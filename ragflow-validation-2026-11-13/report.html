F01 и F02: что подтверждено
реальными HTTP-запросами

Дополнение к исходному security review RAGFlow от 10 ноября. Только две указанные находки, синтетические данные и существующий контейнер. Исходный завершённый scan не изменён.

F01 · нарушение scope подтверждено

Beta раскрывает приватные коллекции через MCP

Ключ, работающий с app A, получил имя и ID приватной B через MCP. В app A включена только коллекция A.

В этой лабе nginx блокирует MCP. Успешный тест выполнялся к API из контейнера; чтение текста через MCP не подтверждено.

F02 · доступ к содержимому подтверждён

Деактивация не отзывает API / beta

После is_active=0 старый API-ключ скачал исходный документ B через nginx. Beta продолжил открывать app-info.

Старая веб-сессия и новый вход с паролем были отклонены. Значит, деактивация сработала, но не для всех видов credentials.

F01 — расширение scope beta до владельца

Созданы отдельный пользователь, две приватные коллекции A-SHARED и B-PRIVATE, по одному текстовому документу и приложение APP-A. Приложение связано только с A. API/beta-пара выпущена обычным endpoint создания ключа; beta отдельно успешно прошёл GET /api/v1/chatbots/:id/info.

Для MCP-запросов передавался только beta. initialize завершился успешно, а tools/list и ragflow_list_datasets вернули B: 38548adedd5348b081927cd9efc1cf9f, имя CODEX-VALIDATION-50088678-B-PRIVATE. Отсутствующий и неверный ключ были отклонены; обычный dataset API отверг beta с HTTP 401.

POST /api/v1/mcp
Authorization: Bearer <beta>
Content-Type: application/json

{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"ragflow_list_datasets",
           "arguments":{"page":1,"page_size":20}}}
Предел доказательства. Запрос ragflow_retrieval для B дошёл до embedding-зависимости и вернул isError:true: соединение к host.containers.internal:1235 отклонено. Успешное чтение текста через MCP не наблюдалось. Список приватных коллекций и потеря границы приложения подтверждены независимо от этого.

Share-ссылка через UI не создавалась: использован реальный beta из той же таблицы/API ключей, которую читает embed-компонент. Браузерное распространение ссылки подтверждено статическим анализом исходного отчёта, а не новым UI-тестом.

На обычном входе лабы POST /api/v1/mcp вернул HTTP 404. Текущий location ^~ /api/v1/mcp { return 404; } ограничивает этот путь. Успешный прямой вызов из контейнера показывает поведение backend и не означает, что запрет nginx обойдён внешним клиентом.

F02 — старые ключи после деактивации

До деактивации проверены session/API/beta. Затем admin API получил PUT /api/v1/admin/users/:username/activate с {"activate_status":"off"}. Отдельный GET состояния подтвердил is_active:"0".

Старая сессия получила HTTP 401. Повторный вход с правильным паролем вернул code:403 и сообщение об отключённом аккаунте. При этом тот же API-ключ получил dataset B и скачал исходный текст по GET /api/v1/datasets/:dataset_id/documents/:document_id через обычный nginx.

Synthetic private test document.
Marker: CODEX_PRIVATE_e0b02e8db69767e8ac8d.
This text belongs only to dataset B …

Старый beta продолжил читать app-info через nginx, а через diagnostic MCP — список коллекций. Доступ ограничен ресурсами прежнего пользователя; произвольный переход в чужой tenant этим тестом не показан.

Практическое следствие: запрет beta не устраняет F02 для обычных API-ключей. Нужны проверка активного состояния в общем resolver и политика отзыва ключей.

Как отключить beta в этой версии

В просмотренном rc3 отдельного конфигурационного переключателя запрета beta не найдено. Прямой способ — безусловно отклонять его в internal/service/user.go:894. Он охватит общую beta-группу, отдельный /searchbots/detail и ResolveMCPUser.

func (s *UserService) ResolveBetaAPIToken(
    _ context.Context,
    _ string,
) (*AuthIdentity, common.ErrorCode, error) {
    return nil, common.CodeUnauthorized,
        fmt.Errorf("beta authentication is disabled")
}

Это предложение, не применённый и не проверенный патч. Нужна сборка нового образа и пересоздание контейнера: изменение upstream/ не заменяет работающий бинарник. Сессии и обычные API-ключи остаются отдельными путями; share/embed на beta перестанет аутентифицироваться. Выдача полей beta в token API и UI этим минимальным изменением не убирается.

После сборки: существующий beta должен отвергаться на всех перечисленных ниже путях; разрешённая session/API-аутентификация должна сохраняться. Для F02 отдельно проверить отказ всех старых credential-классов после деактивации и повторить скачивание тестового документа как отрицательный контроль.

Очистка и воспроизводимость

Через реальные API удалены тестовое приложение, обе коллекции с документами, тестовый ключ и пользователь. Явное удаление ключа дало отрицательный контроль: API — HTTP 401, beta — HTTP 200 / code 102. Admin GET после удаления пользователя вернул code:404. Временный файл с тестовыми credentials удалён.

Конфигурация nginx, runtime-образ, существующие коллекции и защитные настройки не менялись. Только у синтетических документов tokenizer переведён в full_text, потому что реальный embedding-сервис был выключен; оба документа успешно получили по одному chunk. Попытка запуска существующего LM Studio CLI не удалась: daemon/installation не найден. Fake embedding-сервис не поднимался. Проверка lab.sh check после очистки прошла.

  • 71 запись redacted HTTP evidence (JSON) — ответы, последовательность и UTC-время.
  • Фактически использованный harness — исходный setup потребовал адаптации из-за отсутствия embeddings.
  • Упорядоченный helper для повторения — проверен синтаксически, заново целиком не выполнялся.
  • Порядок повторения и ограничения.
  • Машиночитаемые результаты / closure.

Пароли, Authorization и API/beta-значения из сохранённых ответов удалены. В evidence остаются только синтетический маркер и идентификаторы тестовых объектов. Редактор маскирует также некоторые несекретные поля с подстрокой token; это намеренная потеря диагностической детализации.

Локальная целевая валидация. Не полный повторный аудит, не проверка исправления. Исходный sealed scan сохранён отдельно. Последний health check: OK.
